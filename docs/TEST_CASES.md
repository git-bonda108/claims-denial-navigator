# Claims Denial Navigator POC: Test Cases and Expected Outputs

These test cases go with [`POC_PLAN.md`](./POC_PLAN.md). They are implemented in `poc/denialnav/datafactory.py` (scenarios with labels), `poc/tests/` (pytest) and `poc/denialnav/evals.py` (scoring). All data is synthetic, generated by the denial injector in `poc/data-factory/`, which records the ground truth for every case.

Every CARC and RARC code used below was checked against `rhail_codedefinitions.csv` in Microsoft's reference repo.

**How to read the tables**
- *Group* is the CAS group code: **CO** contractual (the provider may not bill the patient), **PR** patient responsibility, **OA** other, **PI** payer initiated.
- *Expected action* comes from the closed action set in `POC_PLAN.md` §6.
- *Must not* lists hard failures. Any violation fails the run, whatever the accuracy.
- Each archetype is generated in about 5 variants (payer, amount, codes, dates), so the golden set has about 100 cases. The bulk eval also runs over all of the roughly 215 synthetic denials.

## 3. Parser and pipeline tests

| ID | Test | Expected |
|---|---|---|
| P01 | 835 with 50 CLP claims | 50 claim records, none dropped (the v1.0 truncation regression test) |
| P02 | One CAS segment with multiple triplets (`CAS*CO*45*100*1*253*2.5~`) | Two adjustments, with the amounts parsed correctly |

| P09 | Corrupted or truncated file | The file is quarantined, the error shows in the UI, and the pipeline continues |
| P10 | End-to-end: drop an 835 in the blob inbox | The worklist updates within 60 s, and a Teams card arrives for any `CRITICAL` item |

## 4. Safety and robustness

| ID | Test | Expected |
|---|---|---|

| S06 | Logs and traces | Patient names and member IDs are masked in App Insights and Foundry traces |
| S07 | Load: one 835 with 500 claims | Processed in under 10 min. The agent is invoked only for non-rule cases. |

## 5. Acceptance targets (golden set, synthetic data)

| Metric | Target | Measured by |
|---|---|---|
| Parser field accuracy and balancing | 100% | P01–P08 |
| Noise filter (zero work items for N01–N04) | 100% | Golden set |
| Action accuracy: rule-decided cases | ≥ 95% | Eval runner vs. labels |
| Action accuracy: agent-decided cases | ≥ 85% | Eval runner vs. labels |
| **"Must not" violations** | **0** | Eval runner |
| Deadline exactness | 100% | D01–D05 plus bulk |
| Groundedness (Foundry evaluator, 1–5) | avg ≥ 4.0 | Foundry evaluations |
| Citation validity (the cited chunk was retrieved and supports the claim) | ≥ 95% | Custom evaluator |
| Output schema validity | 100% | JSON Schema check |
| Latency | rules path < 2 s/claim; agent path p95 < 15 s | App Insights |
| Cost per denied claim | Reported; target set after the first run | Token metering |

All results are reported with a **"synthetic data"** label. Real-world accuracy is established in the pilot (`POC_PLAN.md`, Batch 7).
